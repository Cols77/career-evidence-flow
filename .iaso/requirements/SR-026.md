---
id: SR-026
title: The Codex Stop hook holds a turn's end while the master profile is...
statement: On a Stop event in the bound workspace, the Codex hook returns a block decision naming the
  claim IDs the configured master profile does not name, unless stop_hook_active is true; with no master
  profile, or none missing, it returns nothing, and it still records the event in the session state.
examples:
- id: EX-1
  given: a configured master profile that lacks one claim ID
  when: the Codex hook receives a Stop payload
  then: the output is decision block with a reason naming that claim ID
- id: EX-2
  given: a missing claim ID and stop_hook_active true
  when: the Codex hook receives a Stop payload
  then: the output has no block decision
- id: EX-3
  given: a master profile that names every claim ID
  when: the Codex hook receives a Stop payload
  then: the output has no block decision
- id: EX-4
  given: a workspace that names no master profile
  when: the Codex hook receives a Stop payload
  then: the output has no block decision
proof:
  plan: an independent evaluator runs the installed Codex Stop hook on a synthetic workspace with a claim
    missing from the master profile and sees the stop held with the claim named, then released on the
    second stop
  kind: hook
  evaluator: true
