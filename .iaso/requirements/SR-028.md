id: SR-028
title: Claude Code restores the declared workflow checkpoint after resume...
statement: 'The Claude hooks keep per-session checkpoint state as the Codex hooks do: SessionStart (startup,
  resume or compact) and UserPromptSubmit add the session''s declared skill, phase and freshness to the
  routing context, PreCompact records the event and keeps the declaration, other sessions see nothing
  of it, and cv install-agent --hooks upgrades an existing Claude installation to register PreCompact.'
examples:
- id: EX-1
  given: session S declared application-materials waiting_for_user with cv workflow-checkpoint
  when: session S compacts and SessionStart with source compact fires
  then: the context names application-materials, waiting_for_user and the freshness
- id: EX-2
  given: the same declaration for session S
  when: session T starts
  then: the context names no checkpoint
- id: EX-3
  given: a managed Claude installation registering SessionStart, UserPromptSubmit and Stop
  when: install-agent --hooks runs with the new package
  then: PreCompact is registered too and hooks is updated; a repeat run is unchanged
proof:
  plan: an independent evaluator declares a checkpoint in a Claude Code session on a synthetic workspace,
    compacts it, and sees the restored skill and phase in the next context
  kind: hook
  evaluator: true
