# Resume review rubric

Use concrete observations and source references. Severity: high for unsupported/confidential factual claims or material contradictions; medium for misleading scope, missing material coverage, unreadable/clipped content or incorrect extraction; low for optional stylistic improvements. A label alone does not justify rewriting a supported fact.

| Angle | Questions and common defects |
| --- | --- |
| Whole-document support | Does each identity/contact/date/degree/location/award/summary/skill/bullet fact have actual candidate evidence? Check every subclaim, not only major bullets. Is evidence confirmed/approximate and allowed for publication? |
| Ownership and maturity | Does “led,” “owned,” “delivered” or “deployed” add unsupported ownership or production maturity? Preserve personal versus team contribution, coursework versus employment, prototype versus production, limitations and approximate values. |
| Profile consistency | Are dates, labels, role levels, tooling, scope and numbers consistent with canonical evidence and actual corrections? Superseded claims cannot reappear through old drafts. |
| JD fidelity | Were all source categories extracted? Are direct, transferable and project/course-only mappings honest? Could an unsupported credential or eligibility condition be inferred from phrasing? Company needs cannot prove candidate experience. |
| Pre-draft strengthening | Does the actual JD/profile assessment identify the few valuable opportunities rather than a generic checklist? Before dependent drafting, were material questions answered, already resolved, explicitly skipped, or noncritical items documented as pending and excluded with other sufficient confirmed evidence? Deferral cannot guess eligibility/core fit or use the missing fact. A referenced no-useful-gap conclusion is valid; a token interview is not required. Missing assessment, silent bypass or repeatedly asking answered/declined questions is a medium workflow/content finding, even if draft claims are true. |
| Experience chronology | Are employers and roles within each employer in reverse chronology, including Earlier Experience and continuation pages? Ongoing roles precede completed roles; completed roles sort by descending end date then start date, and ongoing ties by original start date. Check actual source and rendered order, preserve overlaps/resumptions and flag ambiguous dates. An older completed role above newer work is a medium content finding unless the user explicitly requested a documented thematic format. JD relevance alone is not an exception. |
| Skills coherence | Is a listed skill supported, and is proof visible in the same document? Distinguish unsupported, supported-but-not-shown and shown. An exceptional inclusion needs a specific recorded rationale, never a fabricated approval. |
| Skills selection | Does each entry name a useful capability, method or relevant tool at an appropriate level of detail? Assess this separately from evidence support. Routine artifacts, dataset names and minor steps usually belong in an experience bullet, unless role-specific expertise justifies listing them. Report exact entries to consolidate, move or omit; do not inflate their replacements into unsupported MLOps or deployment skills. |
| Profile depth and breadth | Was the full master/actual corrected evidence considered, rather than only the last projection? Within the effective page limit, do selected contributions demonstrate the strongest relevant mechanisms, ownership, delivery and results across distinct capabilities? Identify valuable supported evidence omitted while weaker/repetitive material or avoidable blank space remains. Review the selection rationale; broad coverage does not justify keyword dumping, filler, invented outcomes or unreadably small type. |
| Bullet evidence | Are action, context and outcome understandable and supported? Avoid invented impact percentages, commercial outcomes or tool lists. An honest action without a metric is acceptable. |
| Experiment value | For a strategically relevant experiment, was a missing useful result, evaluation or learning investigated against actual prior answers before drafting? Does the selected evidence explain what was established or enabled where known? Qualitative or negative results can be strong evidence. An explicitly unknown/declined/skipped outcome permits justified narrow wording or omission; lack of a metric alone is not a defect. Report missed material opportunities separately from unsupported claims and optional shortening. |
| Bullet openings and focus | Does every resume bullet start with a supported action verb? Does it combine independently meaningful contributions that should be split? Keep methods, constraints and results of one contribution together; do not split solely by sentence, verb or tool count. Check each resulting bullet's evidence and ownership. Use labelled paragraphs or rows for skill/education inventories rather than forcing them into action bullets. |
| Summary quality | Does a summary add supported role-relevant information, rather than generic excellence claims? No summary is acceptable when it adds little. A headline is still a factual claim. Read it first and alone, as the target recruiter would: can they say what kind of engineer this is and what connects the listed areas? It should lead with what the work achieves before how it works, keep implementation terms in the bullets, avoid defensive hedges that undersell supported facts ("partly", "experimental" without need) and give each sentence one idea. A summary with no throughline, led by jargon or reading as a list of claims is a medium voice and alignment finding, because it is read first. A factual repair to the summary finds simpler wording the evidence supports without qualifiers; it does not append caveats, which belong in the bullet that carries the fact. |
| Voice | Apply the shared [voice and artifact review](../../application-materials/references/voice-and-artifacts.md) against current private writing preferences and authentic samples, where supplied. |
| Cold-reader readability (readability angle) | Reading only the rendered resume and the JD, as the recruiter or a hiring engineer from a neighbouring field would, can you restate each summary sentence and bullet in one plain sentence saying what the candidate did and why it matters? List every term you cannot explain from general engineering knowledge or the JD. A bullet whose point is lost, that opens with mechanism before outcome, that holds several independent contributions or that runs past two lines is a finding: medium when the core point is lost, low otherwise. Repairs replace insider names with general phrases or drop them; they do not add explanations. Factual support belongs to the factual angle. |
| Acronym comprehension | Is an acronym explained where useful? Can the owner actually explain the claimed work? Ask only a material unresolved comprehension question; do not invent their answer. |
| Visual readability | Inspect all pages of actual ATS and branded output: hierarchy, font size, clipping, whitespace, page breaks, orphan headings, bullet wrapping and links. Keep professional links with contact information above the header divider, with readable spacing. Never infer this from source Markdown. |
| Page balance | Compare every page's content endpoint/bottom gap with adjacent pages and inspect manual breaks. An avoidable large blank region before a fuller following page, or a nearly empty final page after a dense first page, is a medium visual finding. A deliberate section boundary or passing page count alone does not justify it. Resolve `layout_audit` signals using the actual page images and record any specific false-positive explanation. Consider normal margins, final-page space and content that actually fits; preserve chronology, readable type, meaningful evidence and heading/bullet integrity during repair. |
| Extraction and policy | Run checks on exact outputs; interpret `artifact_audit` using the shared reference. Compare actual PDF page count with effective policy. HTML checks have no reliable page count. Verify names/contacts and text order, without inventing mandatory headings or contacts. |
| Revision freshness | Are review inputs current, including corrections, answers and effective policy? Was a new render produced after edits? Manually stale old notes; current tooling has no authenticated closure or release gate. |

## Existing commands

Use actual workspace-relative paths:

```text
cv check --workspace ROOT --document outputs/SLUG/r01/resume-ats.html --policy applications/SLUG/effective-policy.json
cv check --workspace ROOT --document outputs/SLUG/r01/resume.pdf --policy applications/SLUG/effective-policy.json
```

The policy path is a standalone complete effective-policy JSON object, not `application.json`. For regeneration, the author uses `cv render` with current source and a fresh revision path. Check output is structural/extraction evidence, never factual entailment, visual proof or submission approval.
