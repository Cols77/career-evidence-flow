# Resume review

Review the actual resume independently of its author. Read [the review packet](references/review-packet.md) and [the rubric](references/rubric.md). Python checks assist your judgment; they cannot establish factual entailment or visual quality.

1. Obtain current evidence and registry, actual answers, pre-draft strengthening assessment/dispositions, projection, complete frozen JD and requirements, effective policy, resume source and exact ATS/branded artifacts. Identify missing inputs and previous revisions. Synthetic fixtures cannot approve real candidate documents.
2. If you authored the draft, dispatch real independent subagents using the host's available delegation tool. Give reviewers fresh context, actual files and bounded assignments. If already acting as an independent reviewer, review directly. A single reviewer may cover multiple angles with separate verdicts. Never fabricate reviewer identities, tool runs or findings.
3. Check every factual unit, including identity, contacts, dates, education, awards, headline, summary, skills and bullets. Require publishable evidence and preserve limitations, prototype/coursework scope and team attribution. Separate unsupported claims from supported claims absent from the document. The JD supports employer needs, never candidate facts.
4. Assess profile consistency, role alignment, keyword meaning, skills coherence, bullet evidence, summary usefulness, human voice and acronym comprehension. Compare selected depth/breadth and important omissions against the full corrected master and JD. Verify that the strengthening assessment considered actual profile opportunities and material questions were answered, previously resolved, explicitly skipped or noncritical items explicitly deferred/excluded with other sufficient confirmed evidence; a justified no-question assessment is valid. Pending facts cannot support claims or unresolved eligibility/core-fit decisions. Review experiment evidence for useful supported outcomes/learning without demanding metrics or inventing impact. Enforce reverse chronology between employers and within employers, including overlaps, resumed roles and page continuations, using the drafting reference's ordering rules. Distinguish concrete workflow/content defects from optional editorial preferences. Do not assign an AI-authorship probability.
5. Inspect the full rendered ATS and branded artifacts with available visual tools, including every PDF page when PDF is requested. Compare adjacent-page fill and record bottom gaps/content endpoints; avoidable large blank space and premature manual breaks are findings even when page limits pass. A clean section boundary alone does not justify wasted space. Check layout, clipping, pagination, typography, readability and text extraction. Run `cv check --workspace ROOT --document PATH --policy EFFECTIVE_POLICY_PATH`; resolve `layout_audit` signals against actual images, not only the structural status. Automated HTML checks cannot establish PDF page limits or visual approval.
6. Return separate factual/profile, alignment/content, voice/comprehension and visual/artifact verdicts with exact affected units, evidence references, severity and proposed repairs. Record each one with `cv record-review --document resume --angle factual|alignment|voice|visual` against the reviewed bundle; `cv review-status` shows which angles still lack a current verdict. Record actual reviewer/run evidence and inspected revisions. The author owns repairs; review at most two repair/review rounds, then disclose remaining defects.

For Codex continuation, read `cv workflow-status --workspace ROOT --session-id ID` using lifecycle context's actual session ID. Save `cv workflow-checkpoint --workspace ROOT --session-id ID --skill resume-review --phase working` with repeated `--file RELATIVE_PATH` for the complete packet and exact source/rendered revisions. Snapshot before review; preserve the selection when deliberately replacing a checkpoint. Record actual independent agent/tool references, inspected pages and findings in private notes. A child reviewer without its own hook metadata returns findings to the author; never invent a session or overwrite the author's checkpoint using their ID.

After compaction/interruption, re-read the packet/findings and respect current user direction. Run `workflow-status` before final claims/copying outputs: `stale` requires affected real reviews on new bytes; `not_recorded` provides no freshness evidence. Even `fresh` only means selected bytes match; it cannot prove a complete packet or that delegation/visual tools ran. Compare any exported copy with the exact reviewed artifact. Hooks never force review continuation or authorize export.

If delegation, source access or visual inspection is unavailable, say precisely which angles remain unreviewed and retain preview status. Same-author sequential passes and scripted fixtures are not independent reviews.

Even genuine reviews are working notes: authenticated claim maps, enforced freshness and guarded release are unavailable. No review here approves submission or changes the CLI's unreviewed-preview status.
