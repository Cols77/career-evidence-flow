# Resume review packet and independent delegation

## Gather the actual revision

Prefer a `cv build-application` bundle and run `cv verify-bundle --workspace ROOT --bundle outputs/SLUG/REVISION/bundle.json` before inspection. Read its frozen `inputs/`, `checks.json`, `review-packet.md` and exact artifacts. Check that the host included actual support sources, prior answers and strengthening notes; automatic selection covers standard records only. Freshness verifies selected bytes, not completeness, reviewer identity or approval. Keep review notes outside the immutable bundle.

The author supplies explicit workspace/application paths, canonical evidence and registry, projection, questions with actual answers/history, pre-draft strengthening assessment and dispositions, frozen JD and requirements, effective policy, Markdown, generated ATS/branded artifacts and relevant check results. The assessment is an ordinary private working note, not an authenticated schema. Inspect the source files rather than relying only on the author's summary. Request missing exact artifacts; a different revision is not interchangeable.

Record filenames and actual raw-byte hashes when the host can compute them. Do not invent hashes or infer exact inspected bytes from a filename. Record real tool/run identity only when the host exposes it. An unavailable identity remains unavailable. Keep notes local; do not disclose private candidate packets to an external service without authorization.

Working support notes may name source units, claim IDs, answer IDs, evidence limitations and proposed wording. They are not authenticated claim maps. Registry fingerprints are declarations, not proof of source-byte freshness.

Follow support references to the actual source and answer files consulted, including answers stored under older applications. Include those files in the review packet and freshness snapshot; evidence summaries, registry hash declarations and the current application's questions alone do not cover them. State any unavailable source or omitted input. When reusing an earlier review of unchanged content, preserve its findings and include its source dependencies in the current packet. A matching selected-file snapshot establishes only that selection's bytes, never completeness.

## Delegate through the real host

Use the actual available subagent tool. Give each agent the task and explicit authorized packet; avoid unrelated personal files. These assignments are independent review tasks, not simulated reviewer personas in the author's conversation. If slots are limited, run them sequentially in fresh independent contexts. One reviewer can cover several assignments but must return each angle separately.

Suggested factual/profile assignment:

> Review the current resume independently; do not edit. Read the actual evidence, registry, answers, projection and source. Check every factual subclaim, identity/contact, date, education, award, summary, skill and bullet. For each defect, name the unit and evidence IDs, unsupported addition or contradiction, severity and a narrow repair. Preserve publication restrictions, ownership, team attribution, prototype maturity and approximation. Distinguish unsupported from supported-but-not-shown skills. Report missing packet inputs. Do not call a structural pass semantic approval.

Suggested alignment/content assignment:

> Independently compare the complete frozen JD, requirement mappings, effective employer policy and actual resume. Inspect the pre-draft strengthening assessment and actual answer/disposition references: identify missed high-value opportunities, unnecessary/repeated questions or silent bypasses, while accepting a justified no-question conclusion. Check useful supported outcomes or learning for relevant experiments without requiring metrics or successful production deployment. Verify reverse chronology between employers and among employer roles, including overlapping/resumed assignments and manual page continuations, against the drafting reference. Check coverage, transferable versus direct experience, keyword meaning, summary usefulness, skill proof and bullet clarity. Explicitly assess whether each skills entry is a useful capability, method or tool, rather than a routine artifact or minor step better placed in experience. This selection verdict is separate from factual support. The JD cannot establish applicant facts. Return angle-specific findings and avoid adding unsupported words merely for keyword matching.

Suggested voice/comprehension assignment:

> Independently apply the [shared voice criteria](../../application-materials/references/voice-and-artifacts.md) to the actual resume, private writing preferences and any supplied authentic samples. Check every bullet for an action-led opening and one clear contribution; identify independent contributions to split without separating an action from its methods or result. Check acronym comprehension; identify terminology whose owner comprehension needs a material question. Return the existing voice/comprehension verdict with exact affected passages.

Suggested visual/artifact assignment:

> Inspect every page of the exact generated ATS and branded resume using actual visual tools. Compare adjacent-page density and record content endpoints/bottom gaps; flag avoidable large blank regions and premature manual breaks even when two pages pass. Resolve the PDF `layout_audit` observations from actual page images, giving a specific justification for any false positive; a clean section transition alone is insufficient. Check clipping, pagination, font size, whitespace, hierarchy, extraction order and source/artifact consistency. Verify that page breaks/continued-employer sections preserve reverse-chronological role order rather than moving an older completed role ahead of newer work. Compare observed output with configured limits and available `cv check` results. State tool limitations and uninspected pages; do not approve an artifact you could not view.

## Return format

Use plain review notes, not an invented toolkit production schema:

```text
Reviewer/run: actual host-provided identity, or unavailable
Inspected inputs: actual paths and revision/hash observations
Factual/profile verdict: no findings | findings | unreviewed
Alignment/content verdict: no findings | findings | unreviewed
Voice/comprehension verdict: no findings | findings | unreviewed
Visual/artifact verdict: no findings | findings | unreviewed
Findings: severity; affected unit/page; evidence or observation; repair
Missing inputs/tools: actual limitations
Remaining risks: specific unresolved issues
```

“No findings” describes that review, not release approval. Check factual findings against the evidence before editing. Repair supported defects, render a new revision and re-review affected angles. At most two repair/review rounds; disclose remaining issues rather than repeatedly invoking identical reviewers against unchanged rejected artifacts.

Changes to evidence, answers, projection, JD, policy, Markdown, styles or final artifact bytes stale dependent notes. The host must track this manually. Automatic freshness enforcement and guarded exact-byte release are not implemented. Even all angles reviewed does not make the toolkit a submission or approval system.
